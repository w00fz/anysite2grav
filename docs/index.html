Manual installation / development

Clone a working copy, then link the skill:

git clone https://github.com/w00fz/anysite2grav.git ~/Projects/anysite2grav
mkdir -p ~/.agents/skills
ln -s ~/Projects/anysite2grav/skills/anysite2grav ~/.agents/skills/anysite2grav

Update this working copy with git pull.

Run these inside Claude Code:

/plugin marketplace add w00fz/anysite2grav
/plugin install anysite2grav@anysite2grav

Update with /plugin marketplace update anysite2grav.

Compare. Refine. Repeat.

Check every route. Refine every detail.

The first pass is a draft. Finish a representative page, then compare each design family against the source: exact layout and styles, working features, and content you can edit.

  • Every route checked. Titles, text, images, redirects, language tags, noindex and analytics.
  • Layouts and states compared. Desktop, tablet and mobile measurements, full-color screenshots, hover, focus and open states.
  • Forms submitted in a browser. A saved record or captured email backs the success message.
  • Editable content verified. Matching page and module blueprints, Markdown content, and a real Admin or MCP edit-and-save check.

For the curious

Under the hood.

The workflow is explicit, the scripts are rerunnable, and the important choices stay yours.

01All 13 checkpoints
  1. Confirm the plan. URL, folder, runtime and agent clients.
  2. Install Grav + Admin2. Start the server and verify Admin login.
  3. Connect API + MCP. Create the local launcher; verify an agent can list pages.
  4. Discover every route. Read robots and sitemaps, crawl links, detect soft 404s, redirects, languages and PDFs.
  5. Review the audit. Trackers and IDs, forms including popups, embeds, custom code, fonts and palette.
  6. Make the choices. Theme name, Tailwind or built-in CSS, languages, form delivery, CAPTCHA and analytics. Nothing is built until you answer.
  7. Extract and import. Text, cards, galleries, video and modals; download media once and deduplicate by SHA-256.
  8. Build the pages. Markdown and frontmatter only, never copied HTML: blueprints, source provenance, shared sections and redirects. Lint with Grav's YAML parser.
  9. Create the theme. Finish a representative page with dedicated templates and blueprints, exact responsive styling, editable content and matching plugin output. Tailwind remains optional.
  10. Connect the forms. Grav Form pages with inline submission, selected delivery and browser tests.
  11. Handle analytics. Port approved tags only to the selected production hosts.
  12. Iterate to parity. Compare component geometry, exact styles and interaction states at desktop, tablet and mobile widths. Check every route and all required features. Missing controls remain incomplete; screenshot scores are never acceptance.
  13. Verify and hand over. Route report, YAML lint, clean Grav log, a real edit, credentials location and remaining provider or licensing needs.

Each stage has a check before the next begins. Your custom fixes stay in rerunnable migration/fixups/ scripts. You decide when the visual match is close enough.

02Your choices, defaults and safeguards

Runtime & agent access

PHP's built-in server by default, Docker + Mailpit, or Valet / Herd / MAMP. Choose the folder and clients: Codex, Claude Code, Cursor or another agent. Global client config changes require your approval.

Theme & styling

Name your theme. Choose Tailwind 4 for ongoing design work or plain CSS with tokens before detailed styling begins. DESIGN.md records the decisions.

Languages

Native Grav multilang when hreflang maps translations, or separate trees per language prefix. Titles, descriptions, Open Graph and language tags come across.

Form delivery & success

Save to user/data, send through SMTP, use a webhook or keep an embed. Choose an inline message or redirect. The message reflects what actually happens.

CAPTCHA

Grav's built-in Cap is the default: self-hosted, invisible and no keys required. Turnstile and reCAPTCHA are alternatives.

Analytics

Port on production hosts only, add consent gating, retain selected tags or drop them. Local and preview traffic stays out of production analytics.

  • Preserve source URLs. Ask before renaming; add 301 redirects for approved changes.
  • Keep authoring private. Admin2, API and MCP are authoring tools and should not be exposed in the production profile.
  • Protect local copies and secrets. Noindex meta and headers on preview hosts; no printed, logged or committed keys. SMTP passwords stay in environment variables.
  • Use real integrations. No guessed form endpoints or pretend success messages. Confirm copied font licenses before production.
  • Prefer Grav's built-ins. Form, Cap, Email, page media and native multilang. Theme JavaScript has no dependencies or jQuery.

├── bin/grav-mcp          # launcher reads the key at startup
└── .mcp.json             # project MCP configuration

Scripts write the bulk; Admin and MCP handle later edits. The page tree is generated on disk. Later agent edits use the API with conflict checks. Theme rebuilds preserve your settings and custom CSS; replacing them requires an explicit reset flag. Shared sections are stored once. Distinct source compositions get dedicated page or module templates with matching blueprints and named Admin fields.

Only grav/user needs a Git repository, if you choose one. Accounts, submissions, credentials and caches are excluded. Local credential files use restrictive permissions; agent configurations point at the launcher rather than containing a key.

05What your machine needs

PHP 8.3+ or Docker

Extensions: curl ctype dom gd json mbstring openssl session simplexml xml zip. Recommended: intl yaml apcu opcache. Docker brings its own runtime.

Python 3.9+

Standard library only. No pip installation for crawling, extraction or page building.

Node 20+

For Grav MCP, Tailwind and Playwright. Installed as needed inside the migration project.
